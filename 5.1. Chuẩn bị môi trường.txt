5.1. Chuẩn bị môi trường
Để triển khai toàn bộ hệ thống EngGo trên AWS theo chuẩn kiến trúc Cloud, bạn cần chuẩn bị các công cụ và tài nguyên cơ bản sau:

1. Tài khoản & Quyền truy cập (AWS IAM)

AWS Account: Đảm bảo tài khoản AWS đang hoạt động ở Region ap-northeast-1 (Tokyo).

IAM User/Role: Tạo IAM User có quyền quản trị hoặc gán các Policy tối thiểu: AmazonVPCFullAccess, AmazonRDSFullAccess, AmazonS3FullAccess, AmazonEC2ContainerRegistryFullAccess, AmazonSSMFullAccess.

2. Công cụ cài đặt trên máy Local (Dev Environment)

AWS CLI v2: Đã cài đặt và cấu hình credentials bằng lệnh aws configure (truyền AWS Access Key ID, AWS Secret Access Key, Region ap-northeast-1).

Docker & Docker Desktop: Dùng để build Docker Image cho ứng dụng Spring Boot Backend.

JDK 21 & Maven: Dùng để đóng gói source code Backend (.jar).

Git: Dùng để quản lý nguồn mã nguồn dự án enggo-backend.

3. Danh sách thông số quy hoạch mạng (VPC Planning)

VPC CIDR Block: 10.0.0.0/16

Availability Zones (AZs): ap-northeast-1a và ap-northeast-1c

Public Subnets: Dành cho Internet Gateway, Application Load Balancer (ALB), NAT Gateway.

Private Subnets: Dành cho Backend (ECS/EC2) và Cơ sở dữ liệu (Amazon RDS MySQL).

Cách kiểm tra thành công: Mở Terminal chạy lệnh aws sts get-caller-identity, kết quả trả về đúng Account ID và UserId của bạn.

.2.4. Tạo NAT Gateway
NAT Gateway (Network Address Translation Gateway) cho phép các tài nguyên trong Private Subnet (như các ECS Task chạy ứng dụng Spring Boot Backend, máy chủ RDS MySQL) có thể chủ động ra Internet để tải bản cập nhật, tải thư viện dependencies, hoặc gửi dữ liệu qua các dịch vụ bên thứ ba mà không bị lộ địa chỉ IP công cộng ra bên ngoài.

1. Thông số cấu hình NAT Gateway
Thông số	Giá trị cấu hình	Giải thích
Name	enggo-nat-gw	Tên định danh cho NAT Gateway.
Subnet	enggo-public-subnet-1a	Bắt buộc đặt trong Public Subnet để giao tiếp với Internet.
Connectivity type	Public	Sử dụng cho lưu lượng đi ra Internet công cộng.
Elastic IP Allocation	Elastic IP tự sinh	Địa chỉ IP Tĩnh công cộng dành riêng cho NAT Gateway.
2. Các bước thực hiện trên AWS Management Console
Truy cập AWS Management Console → Dịch vụ VPC → Chọn NAT gateways ở menu bên trái.

Nhấn nút Create NAT gateway.

Điền các thông tin cấu hình:

Name: enggo-nat-gw

Subnet: Chọn enggo-public-subnet-1a

Connectivity type: Chọn Public

Tại mục Elastic IP allocation ID, nhấn nút Allocate Elastic IP để hệ thống tự động gán một IP Tĩnh công cộng mới.

Nhấn nút Create NAT gateway.

Lưu ý: Quá trình khởi tạo NAT Gateway sẽ mất khoảng 1–3 phút để chuyển sang trạng thái sẵn sàng hoạt động.

3. Hướng dẫn khởi tạo bằng AWS CLI

entity/: Khai báo các đối tượng JPA ánh xạ trực tiếp tới bảng trong CSDL tienganh_app.

Cấu hình AWS CodeBuildAWS CodeBuild tự động hóa quy trình biên dịch mã nguồn enggo-backend, đóng gói Docker Image và push lên Amazon ECR khi có code mới.1. Tạo tệp buildspec.yml ở thư mục gốc mã nguồn:YAMLversion: 0.2

phases:
  pre_build:
    commands:
      - echo Logging in to Amazon ECR...
      - aws ecr get-login-password --region $AWS_DEFAULT_REGION | docker login --username AWS --password-stdin $AWS_ACCOUNT_ID.dkr.ecr.$AWS_DEFAULT_REGION.amazonaws.com
      - REPOSITORY_URI=$AWS_ACCOUNT_ID.dkr.ecr.$AWS_DEFAULT_REGION.amazonaws.com/enggo-backend
      - COMMIT_HASH=$(echo $CODEBUILD_RESOLVED_COMMIT_HASH | cut -c 1-7)
      - IMAGE_TAG=${COMMIT_HASH:-latest}
  build:
    commands:
      - echo Build started on `date`
      - echo Building the Docker image...
      - docker build -t $REPOSITORY_URI:latest .
      - docker tag $REPOSITORY_URI:latest $REPOSITORY_URI:$IMAGE_TAG
  post_build:
    commands:
      - echo Build completed on `date`
      - echo Pushing the Docker image...
      - docker push $REPOSITORY_URI:latest
      - docker push $REPOSITORY_URI:$IMAGE_TAG
      - echo Writing image definitions file...
      - printf '[{"name":"enggo-backend","imageUri":"%s"}]' $REPOSITORY_URI:$IMAGE_TAG > imagedefinitions.json
artifacts:
  files: imagedefinitions.json

Giám sát hệ thống5.10.1. Cấu hình Amazon CloudWatchAmazon CloudWatch được sử dụng để theo dõi hiệu năng và thu thập Log từ các dịch vụ (ECS Fargate, RDS MySQL, ALB).1. Quản lý Log (CloudWatch Logs):Log Group: /ecs/enggo-backend tự động thu thập stdout/stderr từ các ECS Tasks running Spring Boot.Giúp truy vết các lỗi như runtime exceptions, kết nối CSDL, hoặc lỗi xác thực JWT.2. Các chỉ số hiệu năng chính (Metrics & Alarms):ECS Service Metrics:CPUUtilization: Tạo Alarm cảnh báo nếu CPU $> 80\%$ trong 5 phút.MemoryUtilization: Cảnh báo khi RAM $> 80\%$.RDS Metrics:DatabaseConnections: Số lượng kết nối tới CSDL tienganh_app.FreeStorageSpace: Cảnh báo khi dung lượng lưu trữ khả dụng $< 2\text{ GB}$.ALB Metrics:HTTPCode_Target_5XX_Count: Cảnh báo khi số lượng lỗi 5xx từ Backend gia tăng.TargetResponseTime: Theo dõi độ trễ phản hồi của API.5.11. Kiểm thửSau khi hoàn tất hạ tầng, tiến hành kiểm thử toàn diện hệ thống:1. Kiểm thử đơn vị & Tích hợp (Unit & Integration Testing):Chạy test suite của Spring Boot bằng lệnh mvn test để đảm bảo logic nghiệp vụ, repository tương tác CSDL tienganh_app không bị lỗi.2. Kiểm thử API qua ALB (End-to-End API Test):Sử dụng Postman gửi request đến DNS của ALB:POST http://<ALB-DNS>/api/v1/auth/login: Xác thực tài khoản và nhận về JWT token.GET http://<ALB-DNS>/api/v1/topics: Lấy danh sách chủ đề học tập.3. Kiểm thử tải & Kết nối Real-time (WebSocket / Load Testing):Sử dụng công cụ (như JMeter hoặc wscat) tạo kết nối tới Endpoint /ws/pvp để xác nhận kết nối WebSocket duy trì ổn định nhờ cấu hình Sticky Sessions trên ALB.4. Kiểm thử chịu lỗi (Failover & High Availability):Tắt thủ công 1 ECS Task trong Public/Private Subnet $\rightarrow$ Kiểm tra ALB tự động điều hướng lưu lượng sang Task còn lại mà không làm gián đoạn hệ thống.5.12. Dọn dẹp tài nguyênSau khi hoàn tất kiểm thử hoặc kết thúc buổi báo cáo Workshop, tiến hành xóa các tài nguyên theo thứ tự ngược lại để tránh phát sinh chi phí AWS ngoài ý muốn:1.Xóa ECS Service & Cluster:1-2 min.Truy cập ECS Console, hạ desired-count của enggo-backend-service về 0, xóa Service và xóa enggo-cluster.2.Xóa Load Balancer & Target Group:2 min.Xóa enggo-alb và xóa enggo-backend-tg.3.Xóa Amazon RDS & S3 Bucket:3 min.Xóa Database Instance enggo-db (Bỏ chọn 'Create final snapshot' nếu là lab). Empty và xóa S3 Bucket enggo-media-bucket.4.Xóa NAT Gateway & Elastic IP:2 min.Xóa enggo-nat-gw và Release Elastic IP tương ứng.5.Xóa VPC và các tài nguyên phụ thuộc:2 min.Xóa enggo-igw, VPC Endpoints, Route Tables, Subnets, Security Groups và cuối cùng là enggo-vpc.Lưu ý quan trọng về Chi phíBắt buộc phải xóa NAT Gateway và Elastic IP vì đây là các tài nguyên tính phí theo giờ bất kể bạn có truyền dữ liệu hay không.
